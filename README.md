# Лист → Календарь

Статический прототип для переноса рукописного недельного планера в Google Calendar. Сервер приложения и сборка не нужны. Для необязательного режима ИИ пользователь вводит собственный Gemini API Key.

## Что работает

- Недельная сетка, листание недель, локальные черновики, изменение и удаление черновика.
- Выбор, перетаскивание или вставка фото из буфера обмена. Масштаб и лупа помогают выделить отдельные записи. Несколько выделенных фрагментов можно распознать по очереди через [Tesseract.js](https://github.com/naptha/tesseract.js) с русским языковым пакетом, поправить вручную и перенести нужный текст в название. Распознавание целой страницы, дат и времени не реализовано. Первый запуск загружает код и языковой пакет.
- Подключение Google через браузерный OAuth, загрузка событий текущей недели и запись подтверждённого черновика в основной календарь. Изменение и удаление загруженных событий отправляется через Calendar API при активном подключении.
- Простые русские команды: «добавь встречу завтра в 15:00», «перенеси английский на 18:00», «отмени английский». Поиск по названию или курсу может затронуть несколько событий; до выполнения показывается весь список. Без ключа это разбор по правилам.
- Необязательный режим Gemini понимает свободные формулировки создания, поиска, переноса и отмены среди загруженных событий. Введите собственный ключ в разделе «Команды → Gemini для свободных команд». ИИ предлагает действие, приложение проверяет поля и требует подтверждения перед изменением. Ключ исчезает при обновлении вкладки.
- Каждое создание, перенос или отмена требует подтверждения. Данные черновиков сохраняются в `localStorage` этого браузера.

## Запуск

В каталоге проекта выполните `python3 -m http.server 8765` и откройте `http://localhost:8765`. Для базового интерфейса достаточно открыть `index.html`; для OAuth нужен HTTP или HTTPS origin, внесённый в настройки Google.

## Google Calendar

Проект Google Cloud и публичный OAuth Client ID уже настроены для `https://paper-calendar.github.io`, `http://localhost:8765` и `http://localhost:8766`. В интерфейсе нажмите «Подключить Google Calendar» и выберите свой Google-аккаунт. У каждого пользователя свой токен и свой основной календарь; токен живёт только в памяти вкладки и исчезает после перезагрузки.

Пока приложение находится в режиме **Testing**, администратор проекта должен добавить каждый Google-адрес в **Google Auth Platform → Audience → Test users**. Иначе Google покажет ошибку 403 `access_denied`.

Секрет клиента не требуется и не должен помещаться в исходники. Используется область доступа `calendar.events`. В демо-режиме без подключения подтверждение превращает черновик в локальное событие, не отправляя его в Google.

## Gemini API Key

Получите ключ в [Google AI Studio](https://aistudio.google.com/app/apikey). Вставьте его в интерфейсе, затем выберите «Включить ИИ». Ключ остаётся только в памяти открытой вкладки, не записывается в репозиторий и `localStorage`. Запрос идёт из браузера напрямую в Gemini API. Для режима ИИ используется `gemini-3.5-flash-lite`; доступность модели и квоты зависят от проекта. Ключ не нужно передавать автору сайта.

## GitHub Pages

Сайт публикуется из ветки `main`, папки `/ (root)`, по адресу [paper-calendar.github.io](https://paper-calendar.github.io/). В репозитории нет личных фотографий, токенов и секретного ключа.

## Приватность и ограничения

Выбранное фото и вырезанный фрагмент обрабатываются в браузере через Canvas; код не отправляет их на сервер. Для OCR браузер загружает код с jsDelivr и русский языковой пакет Tesseract.js. В режиме ИИ текст команды и краткий список до 80 загруженных событий отправляются в Gemini; фотографии не отправляются. На бесплатном тарифе Google может использовать эти данные для улучшения своих продуктов. Подтверждённые события и их содержание отправляются в Google Calendar API только при подключённом Google. Черновики остаются в `localStorage` без шифрования: не используйте общий браузер для чувствительного расписания.

OCR предназначено для небольших выделенных фрагментов; бледные записи, разные цвета, сжатые фото и рукописные даты могут давать неверный текст. Нечитаемый результат не подставляется автоматически. Без Gemini команды не понимают сложные формулировки. ИИ работает только с уже загруженными событиями, может ошибаться и не создаёт повторяющиеся занятия как серию Calendar recurrence. При изменении нескольких событий запросы к Google идут последовательно; при сетевой ошибке часть уже применённых изменений может сохраниться. Перед подтверждением проверьте список.

## Статус проверки

Проверены синтаксис JavaScript, вставка и перетаскивание тестового изображения, масштаб, лупа, два отдельных фрагмента, распознавание напечатанной русской строки и разбор команды «добавь встречу завтра в 15:00». Режим ИИ проверен с тестовым ответом API; браузер получает ответ Gemini API на запрос с недействительным тестовым ключом. Настоящий ключ пользователя не использовался. На присланном фото мелкий почерк не удалось прочесть уверенно даже после усиления контраста. Google Calendar API включён; оба аккаунта добавлены в тестовые пользователи. На опубликованном сайте OAuth прошёл до статуса «Google подключён» для `xeningem@gmail.com`. Вход второго аккаунта не проверен.
