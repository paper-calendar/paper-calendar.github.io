# Лист → Календарь

Статический прототип для переноса рукописного недельного планера в Google Calendar. Сервер приложения, сборка и секретный ключ не нужны.

## Что работает

- Недельная сетка, листание недель, локальные черновики, изменение и удаление черновика.
- Выбор фото и выделение отдельной рукописной строки. Экспериментальное OCR запускается в браузере через [Transformers.js](https://huggingface.co/docs/transformers.js) и модель [Mievst/trocr-base-handwritten-ru-ONNX](https://huggingface.co/Mievst/trocr-base-handwritten-ru-ONNX). Результат попадает в поле названия и требует ручной правки. Распознавание целой страницы, дат и времени не реализовано. Первый запуск загружает крупные веса модели; на слабом устройстве он может завершиться ошибкой или работать медленно. OCR на реальном фото пользователя пока не проверен.
- Подключение Google через браузерный OAuth, загрузка событий текущей недели и запись подтверждённого черновика в основной календарь. Изменение и удаление загруженных событий отправляется через Calendar API при активном подключении.
- Простые русские команды: «добавь встречу завтра в 15:00», «перенеси английский на 18:00», «отмени английский». Поиск по названию или курсу может затронуть несколько событий; до выполнения показывается весь список. Это разбор по правилам, не свободный чат.
- Каждое создание, перенос или отмена требует подтверждения. Данные черновиков и Client ID сохраняются в `localStorage` этого браузера.

## Запуск

В каталоге проекта выполните `python3 -m http.server 8765` и откройте `http://localhost:8765`. Для базового интерфейса достаточно открыть `index.html`; для OAuth нужен HTTP или HTTPS origin, внесённый в настройки Google.

## Google Calendar

1. В Google Cloud создайте проект, включите Google Calendar API, настройте OAuth consent screen и создайте **OAuth Client ID → Web application**.
2. Добавьте точный origin сайта, например `http://localhost:8765` или `https://USERNAME.github.io`, в **Authorized JavaScript origins**. Для тестового OAuth-приложения добавьте себя в тестовые пользователи.
3. В интерфейсе откройте «Подключить Google Calendar», вставьте Client ID и нажмите «Подключить Google». Адрес сайта для Authorized JavaScript origins можно скопировать прямо из окна настройки. Токен доступа живёт только в памяти вкладки и исчезает после перезагрузки.

Секрет клиента не требуется и не должен помещаться в исходники. Используется область доступа `calendar.events`. В демо-режиме без подключения подтверждение превращает черновик в локальное событие, не отправляя его в Google.

## GitHub Pages

Сайт публикуется из ветки `main`, папки `/ (root)`, по адресу [paper-calendar.github.io](https://paper-calendar.github.io/). Для Google OAuth добавьте `https://paper-calendar.github.io` в **Authorized JavaScript origins** вашего OAuth Client ID. В репозитории нет личных фотографий и учётных данных.

## Приватность и ограничения

Выбранное фото и вырезанный фрагмент обрабатываются в браузере через Canvas; код не отправляет их на сервер. Для OCR браузер загружает код с jsDelivr и веса с Hugging Face. Подтверждённые события и их содержание отправляются в Google Calendar API только при подключённом Google. Черновики остаются в `localStorage` без шифрования: не используйте общий браузер для чувствительного расписания.

OCR предназначено для одной выделенной строки; бледные записи, разные цвета, сжатые фото и рукописные даты могут давать неверный текст. Команды не понимают сложные формулировки, дату переноса или повторяющиеся занятия как серию Calendar recurrence. При изменении нескольких событий запросы к Google идут последовательно; при сетевой ошибке часть уже применённых изменений может сохраниться. Перед подтверждением проверьте список.

## Статус проверки

Проверены синтаксис JavaScript и добавление черновика в браузере. Google OAuth/API и загрузка OCR-модели требуют реального Client ID, сетевого доступа и фотографии для полноценной проверки; в этой начальной версии они не проверены сквозным тестом.
